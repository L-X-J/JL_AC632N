## 1. 结论与数据语义

### 1.1 M601 能测什么

GT-M601 是单点温度传感器。按当前产品假设，它最终直接贴在胸骨附近皮肤上，因此经过佩戴判定和滤波后的 M601 值可以作为“固定贴肤点皮肤温度”使用；从物理测量边界看，它首先仍是传感器所在位置的接触温度，离开人体后同一个读数也可能是环境温度。单个 M601 没有第二温度点、热流、环境温湿度、接触压力或血流信息，因此固件不能仅凭一个读数可靠地泛化为多点平均皮温或核心温度：

- 传感器接触点温度；
- 真实皮肤温度；
- 人体核心温度；
- 脱离人体后的环境温度。

本项目采用以下明确语义：

| 字段 | 语义 | 是否可由当前单 M601 直接得到 |
|---|---|---:|
| `contact_temperature_centi` | 经过滤波的 M601 接触点温度 | 是，通过佩戴窗口的有效样本即可用 |
| `skin_temperature_centi` | 固定胸带位置的皮肤温度（工程上等同于该点接触温度） | 是，不能等同于多点平均皮温 |
| `core_temperature_centi` | 多个有效皮肤样本输入的个体化、实验性核心温度估算 | 否，必须有参考数据标定和验证 |
| 码表平均温度 | 码表对有效核心历史样本的汇总 | 由码表计算，固件不上报平均值 |

### 1.2 发布原则

- `23°C` 这类脱离人体读数、无设备、CRC 错误、范围错误、重复序号和长时间断报，完全不进入有效温度通知流；通过佩戴窗口的预热样本可以作为自定义 CORE 的固定贴肤点皮肤温度，但不得作为核心/HTS/广播值。
- 未知值不能补 `0°C`，也不能重复上一帧伪装成新样本。
- 默认影子模式只记录 M601 皮肤温度、接触温度、候选核心估算、质量、置信度和状态；核心字段保持 `0x7FFF`。
- `EXPERIMENTAL` 是当前采集模式：稳定后同时发送 Skin 和模型 Core 候选，Core 明确标记为未验证，供真实场景记录和后续调整。
- `CONTACT_PROXY` 只作为兼容旧码表的显式配置，表示“稳定的 M601 皮肤/接触温度”重复填入 Core 字段，不代表核心温度。
- 当前 `board/bd19/board_ac632n_rider_cfg.h` 显式选择 `EXPERIMENTAL`；通用头文件仍保持 `SHADOW` 安全默认，便于其他产品复用。
- `STRICT` 只有在标定文件的验证门槛通过、人工审查完成且产品明确接受个体化误差后才能启用。

## 2. 研究依据到工程决策

| 研究观察 | 对本项目的决策 |
|---|---|
| 单点皮温受环境、运动、贴合和个体差异影响，不能直接等同核心温度 | 先分离接触/皮肤代理/核心估算三种语义，不复用一个 `core_temperature_centi` 字段 |
| 单皮温模型容易低估核心温度；加入心率、热流、绝缘皮温等特征可改善模型 | 当前只有单 M601 时不虚构心率、运动、环境或湿度特征；抓包确认 `0x13` 输入后才考虑加入心率 |
| 传感器脱落会产生环境读数和时间序列断裂 | 佩戴窗口、序号连续性、缺失超时、状态机和发布门控必须先于温度编码 |
| 热响应存在滞后，短时尖峰不能直接作为生理变化 | 中值去尖峰 + EWMA + 斜率 + 一阶滞后 + 速率限制 |
| 论文模型的准确性依赖实验条件和验证方法 | 使用连续完整时段留出验证，禁止随机打散时间点造成时间泄漏 |

研究依据不支持“单 M601 已有医疗精度”。本项目的 `<=0.5°C` 是内部工程验收门槛，不是文献对当前硬件的性能承诺。

## 4. M601 原始采集与换算

### 4.1 当前固件采用的 1-Wire 流程

1. PB7 释放为开漏输入，执行 presence reset。
2. 发送 `0xCC`（SKIP ROM）和 `0x44`（CONVERT T）。
3. 等待约 `15 ms`。
4. 再次 presence reset，发送 `0xCC` 和 `0xBE`（READ SCRATCHPAD）。
5. 读取 9 字节 scratchpad，校验字节 8，解析字节 0/1。
6. 失败时递增序号并发布无效样本，温度字段使用 `0x7FFF`。

### 4.2 换算公式

本项目沿用仓库内 [`temp_sample/M601(1).c`](<./temp_sample/M601(1).c>) 的集成示例：

```text
raw_signed = signed16(scratchpad[1] << 8 | scratchpad[0])
temperature_c = raw_signed / 256 + 40
temperature_centi = round_to_nearest(temperature_c * 100)
```

当前驱动使用 Dallas/Maxim CRC-8 的反射多项式 `0x8C`，但随项目资料没有给出 M601 正式 CRC 多项式、初值和完整寄存器定义。这是明确的集成假设，必须在拿到正式《M601/M1601/M1820 高精度温度芯片产品手册》后重新核对。

### 4.3 范围的三层含义

不要混淆以下三个范围：

| 范围 | 当前记录 |
|---|---|
| 手册芯片工作范围 | 手册写明约 `-70°C~+150°C`；精度指标为 `±0.1°C @ +28°C~+43°C`，其他区间另有说明 |
| 当前驱动物理保护 | `-40.00°C~+125.00°C`，用于拒绝异常编码，见 `RIDER_M601_MIN/MAX_TEMP_CENTI` |
| 当前产品佩戴窗口 | `30.00°C~45.00°C`，用于拒绝脱离人体环境读数，例如 `23°C` |

驱动的 `-40~125°C` 不是对手册全部工作范围的重新声明；产品窗口也不是传感器精度范围。三者都应通过实测和正式芯片资料重新校准。

## 5. 滤波、佩戴状态与新鲜度

### 5.1 当前固件参数快照

以下值来自 `apps/rider_core_temp/include/rider_core_temp.h`，修改时必须同步本表：

| 宏/参数 | 当前值 | 单位/格式 | 作用 |
|---|---:|---|---|
| `RIDER_CORE_TEMP_WEAR_MIN_CENTI` | `3000` | 0.01°C | 佩戴下限 |
| `RIDER_CORE_TEMP_WEAR_MAX_CENTI` | `4500` | 0.01°C | 佩戴上限 |
| `RIDER_TEMP_FILTER_MEDIAN_SAMPLES` | `5` | 样本数 | 中值窗口 |
| `RIDER_TEMP_FILTER_EWMA_ALPHA_Q8` | `64` | Q8 = 0.25 | EWMA 响应系数 |
| `RIDER_TEMP_FILTER_STABLE_SAMPLES` | `30` | 样本数 | 正常皮肤区间不连续时的稳定兜底 |
| `RIDER_TEMP_FILTER_NORMAL_SAMPLES` | `5` | 样本数 | 连续正常皮肤区间样本达到后提前进入稳定 |
| `RIDER_TEMP_FILTER_NORMAL_MIN/MAX_CENTI` | `3500/3800` | 0.01°C | 快速稳定区间 `35~38°C` |
| `RIDER_TEMP_FILTER_MAX_GAP_SAMPLES` | `3` | 序号间隔 | 大于此值不桥接历史 |
| `RIDER_TEMP_STALE_AFTER_TICKS` | `3` | 调度 tick | 无新序号约 3 秒后进入陈旧 |
| `RIDER_TEMP_FILTER_SLOPE_LIMIT_CPM` | `150` | 0.01°C/min | 超过后质量降为 Fair |

### 5.2 中值、EWMA 和斜率

设有效接触样本为 `x[n]`，中值窗口输出为 `m[n]`，滤波值为 `f[n]`：

```text
m[n] = median(x[n-4], ..., x[n])
f[0] = m[0]
f[n] = f[n-1] + round((m[n] - f[n-1]) * 64 / 256)
slope_centi_per_min = (f[n] - f[n-1]) * 60 / sequence_gap
```

中值抑制单点尖峰；EWMA 降低量化噪声和短时机械扰动；斜率只用于质量和模型特征，不直接当作核心温度。

为避免整数定点量化把微小趋势永久吞掉，EWMA 在 `delta != 0` 但四舍五入步长为零时保留一个带符号的 `1` 个百分之一摄氏度步长；核心模型则进一步在 Q8 状态中保留小数残差。

### 5.3 状态机

| 状态 | 进入条件 | 输出行为 | 离开条件 |
|---|---|---|---|
| `NO_DEVICE` | presence 失败或传感器不可用 | 全部温度无效；不通知、不广播 | 新的有效总线样本 |
| `NOT_WORN` | 样本低于 `30°C` 或高于 `45°C` | 清空滤波历史；不进入平均值 | 新样本回到窗口并重新预热 |
| `WARMING` | 在佩戴窗口内，尚未达到“连续 5 个 `35~38°C`”且有效样本少于 30 | 自定义 CORE 可发送合法固定贴肤点皮肤温度（Quality=Poor）；核心/HTS/广播关闭 | 连续 5 个正常区间样本，或连续 30 个佩戴窗口有效样本 |
| `STABLE` | 满足任一稳定资格并锁存到本次佩戴 episode | 可发送 M601 皮肤字段；`EXPERIMENTAL` 同时发送算法 Core 候选，`STRICT` 仍受 Good 质量和标定门控 | 无效样本、未佩戴、长间隔或 stale 超时 |
| `STALE` | 序号长间隔，或约 3 秒没有新序号 | 清空测量字段；读值为哨兵/NaN | 新样本到达后回到 `WARMING` |

无效样本会清空历史；不会用最后一个值填补缺口。核心模型和滤波历史在 `STALE` 后都必须重新初始化。

板载诊断 LED 将该状态直接映射为可观察反馈：LED2 绿色只有在 `STABLE + FRESH + status=OK` 时常亮；合法接触但仍在 `WARMING` 时慢闪；无设备时快闪；未佩戴、CRC 错误和陈旧状态不显示稳定灯。LED3 蓝色继续提示 CRC、范围和未佩戴异常。LED 状态只用于调试，不改变 BLE 的有效性门控。

### 5.4 质量、置信度和有效性

- `WARMING`：质量 `POOR`，皮肤温度可观察，核心置信度 0/不可发布。
- `STABLE + 斜率未超限`：质量 `GOOD`，核心模型从多个有效皮肤样本开始更新，初始置信度约 70。
- `STABLE + 斜率超限`：质量 `FAIR`；`EXPERIMENTAL` 仍计算并发送候选供分析，`STRICT` 不发布该样本。
- 传输无效、未佩戴、陈旧：质量 `N/A`，置信度 0。
- 核心候选有效条件：`EXPERIMENTAL` 为存在模型参数、状态稳定且质量至少 `FAIR`；`STRICT` 还要求质量至少 `GOOD`、置信度达到 `70`。
- 核心“已验证”条件：核心候选有效且标定文件明确写入 `RIDER_CORE_TEMP_CALIBRATION_VALID=1`。

## 6. 单传感器核心模型

### 6.1 模型形式

模型只表达固定佩戴位置和个体化实验估算：

```text
target = filtered_contact_centi
       + offset_centi
       + slope_centi_per_min * slope_gain_q8 / 256

core_q8[n] = core_q8[n-1] + (target * 256 - core_q8[n-1]) * lag_alpha_q8 / 256
core[n] = round(core_q8[n] / 256)
```

实现还执行：

```text
35.00°C <= target/core <= 42.00°C
|core[n] - core[n-1]| <= 0.25°C per second
```

首个稳定样本直接初始化滞后状态；后续样本使用一阶滞后和速率限制。滞后状态保留 Q8 小数，因而皮温上升和下降使用完全对称的定点路径，不会因每秒先舍入到百分之一摄氏度而把小幅下降吞掉。`STRICT` 的 `offset_centi`、`slope_gain_q8`、`lag_alpha_q8` 必须由离线数据生成，不能凭经验硬编码。当前 `EXPERIMENTAL` 在没有标定 header 时使用透明的中性起点 `offset=0`、`slope_gain=0`、`lag_alpha=32`，目的是把算法链路输出给码表记录；该输出必须标记为实验候选，不能理解为已校准的核心体温。

### 6.2 心率输入边界

CORE Control Point `0x13` 仍保留外部心率输入和约 15 秒超时，但当前没有证据证明目标码表会写入该字段。因此：

- 没有抓包证据时，模型不依赖心率；
- 不虚构运动强度、环境温度、湿度或热流；
- 后续若确认 `0x13` 有稳定输入，先把心率作为离线特征比较，再决定是否扩展定点模型；
- 当前不输出 HSI，也不输出医疗告警。

## 7. BLE 编码与码表平均值

### 7.1 自定义 CORE 帧

CORE 温度帧为变长帧，字段按 Flags 顺序排列：

| 字段 | 当前策略 |
|---|---|
| Core | 始终存在；严格模式有效时为核心候选，否则 `0x7FFF` |
| Skin | 通过佩戴窗口的 `WARMING`/`STABLE` 样本可附带滤波后的 M601 固定贴肤点皮肤温度 |
| Quality & State | 始终带；低 4 位使用滤波质量，高半字节保留外部心率状态 |
| Heart Rate | 只有 Control Point `0x13` 收到有效值时带出 |
| HSI | 暂不输出 |

当前 `EXPERIMENTAL` 模式在 `WARMING` 发送有效 Skin、Core 无效，在 `STABLE` 同时发送有效 Skin 和多个有效皮肤样本计算出的 Core 候选；没有通过佩戴窗口或数据陈旧时不重复发送有效温度 Notification。`SHADOW` 仍只记录模型，不发布 Core。

### 7.2 标准 Health Thermometer

`0x1809/0x2A1C` 只承担核心语义：

- 核心有效时使用 IEEE-11073 FLOAT，分辨率 `10^-2°C`；
- 核心不可用时使用 NaN mantissa `0x007FFFFF`，指数为 0；
- 影子模式不会把接触温度映射成标准核心温度；
- `0x2A1D` 独立返回 Temperature Type；
- 通知节拍约 10 秒，读取路径仍可返回当前哨兵值。

### 7.3 广播与平均值

- Manufacturer Specific Data 只在核心发布资格成立时带出温度；无效时省略温度字段。
- 断报和 `23°C` 不生成低温样本。
- 码表应对断报暂停平均统计或保持上一有效值，不能把缺失窗口按 0°C 或低温样本参与平均。
- 固件不维护平均温度、不发送平均字段，避免与码表的历史统计口径冲突。

## 8. 离线标定、验证与报告

### 8.1 输入数据

标定工具：`tools/rider_core_temp_calibrate.py`。

```text
timestamp,contact_centi,core_centi,reference_skin_centi,state,session_id
```

支持：

- `contact_centi` / `core_centi` 等百分之一摄氏度整数列；
- `contact_c` / `core_c` 等摄氏度列；
- `m601_raw`，按 `raw / 256 + 40` 转换；
- 可选参考皮温；
- `state=stable`、`3`、`ok` 或 `valid` 才参与拟合。

建议每条记录同时保存：原始 scratchpad、CRC 结果、固件序号、时间戳、佩戴状态、胸带位置/压力、参考核心温度来源、参考皮温位置、心率来源和环境条件。

### 8.2 拟合流程

1. 按时间排序，去掉非稳定和缺少参考值的行。
2. 计算接触温度斜率。
3. 对一阶滞后 `lag_alpha_q8=1..255` 做网格搜索。
4. 对每个滞后参数拟合 `offset` 和 `slope_gain`。
5. 将浮点参数量化为 `offset_centi` 和有符号 Q8 `slope_gain_q8`。
6. 用与固件相同的整数斜率、限幅、滞后、舍入和速率限制重新预测。
7. 输出训练集与完整留出时段的 RMSE、SEE、偏差、浮点结果、定点结果和参考皮温摘要。

工具的最小命令：

```sh
python3 tools/rider_core_temp_calibrate.py samples.csv --output calibration.json --header apps/rider_core_temp/include/rider_core_temp_calibration.h
```

当前 CLI 对单一连续序列默认以前 80% 拟合、后 20% 连续留出。多时段实验应使用完整 Session 留出，命令示例为：

```sh
python3 tools/rider_core_temp_calibrate.py samples.csv \
  --holdout-session exercise \
  --output calibration.json \
  --header apps/rider_core_temp/include/rider_core_temp_calibration.h
```

`--holdout-session` 要求 CSV 提供 `session_id`（也接受 `session`）列，并会把整个时段从拟合集合移除；模型在该时段起点重新初始化。不能把同一运动时段拆到训练集和测试集两边，也不能随机打散时间点。

### 8.3 发布门槛

量化后的留出数据必须同时满足：

```text
RMSE <= 0.50°C
SEE  <= 0.50°C
|bias| <= 0.50°C
```

且不能有明显的温度区间系统性偏差、运动/恢复阶段单独失效或重新佩戴后错误恢复。只有通过门槛并完成人工审查，生成 header 才可把 `RIDER_CORE_TEMP_CALIBRATION_VALID` 置为 `1`；随后还必须显式配置：

```c
#define RIDER_CORE_TEMP_PUBLISH_MODE RIDER_CORE_TEMP_PUBLISH_STRICT
```

门槛失败、数据不足、参考核心温度不可靠或跨时段偏差明显时，继续保持 `SHADOW`。

## 9. 验证矩阵

| 场景 | 期望状态/编码 | 通过标准 |
|---|---|---|
| 传感器未连接 | `NO_DEVICE`，核心 `0x7FFF`，HTS NaN | 不发有效温度，不进平均值 |
| CRC 错误 | 无效快照，清空历史 | 下一次有效样本重新预热 |
| 读数 `23°C` | `NOT_WORN` | 不通知、不广播、不进平均值 |
| 单点尖峰 | 中值/EWMA 抑制 | 不产生同幅核心跳变 |
| 序号重复/间隔过长 | `STALE` | 不桥接缺失，恢复后重新预热 |
| 连续约 3 秒无新序号 | `STALE` | 上一稳定值不再可发布 |
| 稳定佩戴 | `STABLE`，M601 皮肤字段可用 | 当前 `EXPERIMENTAL` 同时发送 Skin 和算法 Core 候选；`STRICT` 还要求验证门槛 |
| 预热佩戴 | `WARMING`，M601 固定贴肤点皮肤字段可用 | 自定义 CORE 可带 Skin 和 `Quality=Poor`；核心/HTS/广播保持无效 |
| 五个正常皮肤样本 | 连续 5 个 `35~38°C` 后锁存 `STABLE` | 核心模型从此开始使用多个有效皮肤样本；单点异常会清零快速计数但不会伪造温度 |
| 核心候选未验证（`SHADOW`） | CORE 核心 `0x7FFF`，HTS NaN | 绝不进入码表核心平均值 |
| 稳定接触 + `EXPERIMENTAL` | CORE 同时带 Skin 和算法 Core 候选；HTS/广播带 Core 候选 | 码表可记录两路数据；Core 仍必须标记为实验值 |
| 严格模式且验证通过 | CORE/HTS/广播可带核心候选 | 参数、版本和报告可追溯 |
| `0x13` 外部心率 | 心率字段可选，超时后清除 | 未收到时不虚构心率/运动特征 |

主机侧回归：

cmake --build cmake-build-clion-ac632n-index --target ac632n_rider_core_temp_indexing -j2

其中 `tools/test_rider_temp_filter.py` 会用主机 C 编译器运行滤波状态机测试，`tools/test_rider_core_estimator.py` 会直接编译生产估算器并验证稳定后皮温下降时 Core 也下降；测试覆盖 `23°C` 未佩戴、窗口内尖峰、中断/CRC 错误、重复序号、预热和稳定边界。M601 总线时序、CRC 实物值和 BLE 抓包仍必须在实板上验证。

## 10. 已知限制和风险

1. 本地 GT-M601 模块手册同时描述了模块 UART `115200 8N1` 的 ASCII 主动上报格式 `A+XX.XB` 加回车换行；当前 AC632N 固件走的是 PB7 直连传感器 1-Wire 路径，必须确认量产硬件没有把模块 MCU UART 输出误当作 PB7 传感器总线。
2. 正式 M601 芯片手册、CRC 多项式、寄存器定义和完整时序尚未进入本仓库；当前 CRC 和 `raw/256+40` 是基于随项目示例的集成假设。
3. `-40~125°C` 是当前固件保护窗，不是对芯片手册 `-70~150°C` 工作范围的替代声明。
4. 单人或小样本的核心估算只能作为固定位置、个体化运动趋势模型，不能跨人泛化，也不能用于医疗诊断或热应激告警。
5. 没有第二温度点、热流、环境温湿度、运动强度和稳定心率之前，不应期待模型具备多参数论文中的精度。
6. 真实测量要覆盖静息预热、持续运动、停止恢复、脱落/重新佩戴、不同环境和不同绑带压力；仅用平稳室温数据不能证明模型有效。

## 11. 后续迭代路线

### 阶段 A：当前实验采集基线

- 当前 AC632N 使用 `EXPERIMENTAL`，稳定后同时收集和上报 Skin 与算法 Core 候选；候选仍未通过验证，不得标记为已验证核心体温。
- 收集原始温度、滤波接触温度、状态、质量、置信度、序号和新鲜度。
- 记录参考核心温度、参考皮温、心率、环境和运动阶段，但不把缺失特征填成 0。

### 阶段 B：个体化标定

- 固定胸骨位置、隔热结构和绑带压力。
- 按完整 Session 留出，分别检查静息、升温、运动、恢复和脱落段。
- 比较固定偏移、接触+斜率、一阶滞后和带心率特征模型。
- 只有定点量化后仍通过门槛，才生成候选 header。

### 阶段 C：实板和码表验证

- 抓取码表是否真实写入 Control Point `0x13`。
- 检查 CORE Flags、皮肤字段、`0x7FFF`、HTS NaN 和广播省略行为。
- 检查断报时码表是否暂停平均统计，而不是把缺失转换成低温。
- 检查 PB7 的上拉、线长、噪声、供电和重启后的状态清空。

### 阶段 D：扩展模型（必须重新验证）

- 若硬件增加第二温度点、热流、环境温湿度或稳定心率，才考虑多参数模型。
- 若要输出热应激等级，必须单独定义临床/运动生理风险边界和误报/漏报验收，不能从核心估算门槛直接推导。
- 若需要跨人泛化，必须扩大受试者、体型、性别、年龄、环境和运动强度范围，并做按人留出验证。

### 12.3 来源核验记录

- PMC 论文页面已核对题名、摘要、作者入口和 DOI；其中 Eggenberger 论文明确报告最小输入模型使用心率和绝缘皮温，SEE 约 `0.29°C`。
- Taylor、Gunga 和 Teunissen 条目的 DOI、题名和期刊元数据已通过 Crossref 公开记录核对；出版社页面可能存在反爬或付费限制，不能把未读取的全文细节写成已验证结论。
- 本地 M601 手册和仓库 `temp_sample` 是实现依据；手册未提供的 CRC 多项式和完整寄存器时序继续标为集成假设。

### 12.4 研究证据等级

- `A`：论文正文/摘要或本地正式手册明确支持；可用于设计约束。
- `B`：公开协议或仓库示例支持；可用于接口和兼容实现，但仍需硬件确认。
- `C`：工程假设或产品初始窗口；只能作为可调参数，不能写成传感器事实。

当前记录：M601 换算和 CRC 假设为 `B/C`；`30~45°C` 佩戴窗口、30 点预热、3 秒 stale 和核心定点模型为 `C`；论文关于单点皮温边界和多参数必要性的结论为 `A`。
