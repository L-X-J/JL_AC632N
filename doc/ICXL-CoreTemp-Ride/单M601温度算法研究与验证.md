## 1. 结论与数据语义

### 1.1 M601 能测什么

GT-M601 是单点温度传感器。按当前产品假设，它最终直接贴在胸骨附近皮肤上，因此经过佩戴判定和滤波后的 M601 值可以作为“固定贴肤点皮肤温度”使用；从物理测量边界看，它首先仍是传感器所在位置的接触温度，离开人体后同一个读数也可能是环境温度。单个 M601 没有第二温度点、热流、环境温湿度、接触压力或血流信息，因此固件不能仅凭一个读数可靠地泛化为多点平均皮温或核心温度：

- 传感器接触点温度；
- 真实皮肤温度；
- 人体核心温度；
- 脱离人体后的环境温度。

本项目采用以下明确语义和三条可对齐时间线：

| 时间线/字段 | 语义 | 是否可由当前单 M601 直接得到 |
|---|---|---:|
| Sensor / `sensor_temperature_centi` | M601 经 CRC 和物理范围校验的直接上报值；用 `sequence` 标识来源 | 是，但可能是接触、环境或异常佩戴温度 |
| Internal Contact / `contact_temperature_centi` | 佩戴保护窗内经过中值和 EWMA 的接触诊断值 | 是，只供状态机和诊断，不等同可信皮温 |
| Trusted Skin / `skin_temperature_centi` | 连续接触门控通过后的固定胸带位置皮温；用 `skin_source_sequence` 对齐 Sensor | 是，仍不能等同多点平均皮温 |
| Experimental Core / `core_temperature_centi` | 可信皮温历史和可选心率输入 Core V1 的实验性估算；用 `core_source_sequence` 对齐 | 否，必须用参考核心温度标定和验证 |
| 码表平均温度 | 码表对有效核心历史样本的汇总 | 由码表计算，固件不上报平均值 |

### 1.2 发布原则

- `23°C` 这类脱离人体读数、无设备、CRC 错误、范围错误、重复序号和长时间断报，完全不进入有效温度通知流；只通过佩戴保护窗但尚未完成连续接触门控的样本仅作为内部 Contact 诊断，不作为可信 Skin 或 Core 上报。
- 未知值不能补 `0°C`，也不能重复上一帧伪装成新样本。
- 默认影子模式记录 Sensor、Contact、Trusted Skin、候选 Core、来源序号、质量、置信度和状态；核心字段保持 `0x7FFF`。
- `EXPERIMENTAL` 是当前采集模式：可信 Skin 建立后稳定发送 Skin；Core V1 独立完成约 5 分钟预热后再发送模型候选。Core 明确标记为未验证，供真实骑行记录和后续调整。
- `CONTACT_PROXY` 只作为兼容旧码表的显式配置，表示“稳定的 M601 皮肤/接触温度”重复填入 Core 字段，不代表核心温度。
- 当前 `board/bd19/board_ac632n_rider_cfg.h` 显式选择 `EXPERIMENTAL`；通用头文件仍保持 `SHADOW` 安全默认，便于其他产品复用。
- `STRICT` 只有在标定文件的验证门槛通过、人工审查完成且产品明确接受个体化误差后才能启用。

## 2. 研究依据到工程决策

| 研究观察 | 对本项目的决策 |
|---|---|
| 单点皮温受环境、运动、贴合和个体差异影响，不能直接等同核心温度 | 先分离接触/皮肤代理/核心估算三种语义，不复用一个 `core_temperature_centi` 字段 |
| 单皮温模型容易低估核心温度；加入心率、热流、绝缘皮温等特征可改善模型 | Core V1 支持 Control Point `0x13` 的真实、未超时心率；没有心率时自动走 Skin-only，不填 0 BPM，不虚构功率、踏频、速度、环境温度或湿度 |
| 传感器脱落会产生环境读数和时间序列断裂 | 佩戴窗口、序号连续性、缺失超时、状态机和发布门控必须先于温度编码 |
| 热响应存在滞后，短时尖峰不能直接作为生理变化 | 中值去尖峰 + EWMA + 斜率 + 一阶滞后 + 速率限制 |
| 论文模型的准确性依赖实验条件和验证方法 | 使用连续完整时段留出验证，禁止随机打散时间点造成时间泄漏 |

研究依据不支持“单 M601 已有医疗精度”。本项目的 `<=0.5°C` 是内部工程验收门槛，不是文献对当前硬件的性能承诺。

## 4. M601 原始采集与换算

### 4.1 当前固件采用的 1-Wire 流程

1. PB7 释放为开漏输入，执行 presence reset。
2. 发送 `0xCC`（SKIP ROM）和 `0x44`（CONVERT T）。
3. 等待约 `15 ms`。
4. 再次 presence reset，发送 `0xCC` 和 `0xBE`（READ SCRATCHPAD）。
5. 读取 9 字节 scratchpad，校验字节 8，解析字节 0/1。
6. 失败时递增序号并发布无效样本，温度字段使用 `0x7FFF`。

### 4.2 换算公式

本项目沿用仓库内 [`temp_sample/M601(1).c`](<./temp_sample/M601(1).c>) 的集成示例：

```text
raw_signed = signed16(scratchpad[1] << 8 | scratchpad[0])
temperature_c = raw_signed / 256 + 40
temperature_centi = round_to_nearest(temperature_c * 100)
```

当前驱动使用 Dallas/Maxim CRC-8 的反射多项式 `0x8C`，但随项目资料没有给出 M601 正式 CRC 多项式、初值和完整寄存器定义。这是明确的集成假设，必须在拿到正式《M601/M1601/M1820 高精度温度芯片产品手册》后重新核对。

### 4.3 范围的三层含义

不要混淆以下三个范围：

| 范围 | 当前记录 |
|---|---|
| 手册芯片工作范围 | 手册写明约 `-70°C~+150°C`；精度指标为 `±0.1°C @ +28°C~+43°C`，其他区间另有说明 |
| 当前驱动物理保护 | `-40.00°C~+125.00°C`，用于拒绝异常编码，见 `RIDER_M601_MIN/MAX_TEMP_CENTI` |
| 当前产品佩戴窗口 | `30.00°C~45.00°C`，用于拒绝脱离人体环境读数，例如 `23°C` |

驱动的 `-40~125°C` 不是对手册全部工作范围的重新声明；产品窗口也不是传感器精度范围。三者都应通过实测和正式芯片资料重新校准。

### 5.2 中值、EWMA 和斜率

设有效接触样本为 `x[n]`，中值窗口输出为 `m[n]`，滤波值为 `f[n]`：

```text
m[n] = median(x[n-4], ..., x[n])
f[0] = m[0]
f[n] = f[n-1] + round((m[n] - f[n-1]) * 64 / 256)
slope_centi_per_min = (f[n] - f[n-1]) * 60 / sequence_gap
```

中值抑制单点尖峰；EWMA 降低量化噪声和短时机械扰动；斜率用于质量、核心模型特征和脱离候选判定，不直接当作核心温度。

为避免整数定点量化把微小趋势永久吞掉，EWMA 在 `delta != 0` 但四舍五入步长为零时保留一个带符号的 `1` 个百分之一摄氏度步长；核心模型则进一步在 Q8 状态中保留小数残差。

5 个样本的唯一资格作用是填满鲁棒中值窗口；它们不能证明传感器已经达到皮肤热平衡，也不能提前进入可信皮温或 Core 模型。当前 30 样本是约 1 Hz 调度下的工程接触确认时间，不代表皮肤已经达到严格热稳态；后续必须用实物贴合曲线校准。

### 5.3 可信皮温状态机

| 状态 | 进入条件 | 输出行为 | 离开条件 |
|---|---|---|---|
| `NO_DEVICE` | presence 失败或传感器不可用 | 全部温度无效；不通知、不广播 | 新的有效总线样本 |
| `NOT_WORN` | 样本低于 `30°C` 或高于 `45°C` | 清空滤波历史；不进入平均值 | 新样本回到窗口并重新预热 |
| `CONTACT_SETTLING` | 样本连续落在 `30~45°C` 保护窗，但有效接触少于 30 个样本 | 保留 Contact 诊断；Skin/Core Notification 均不发布 | 第 30 个连续有效样本进入 `SKIN_TRUSTED`；任一无效/断序会重置 |
| `SKIN_TRUSTED` | 连续 30 个有效接触样本，资格锁存在当前佩戴 episode | 约 1 Hz 发布可信 Skin；Core 是否可用由独立状态机决定 | 无效样本、未佩戴、长间隔、stale 或脱落候选 |
| `DETACH_SUSPECTED` | 斜率达到 `-1.80°C/min` 即进入候选；连续至少 5 个样本无明显回升且累计下降 `0.50°C` 后锁存脱落 | 候选开始即暂停可信 Skin/Core；未确认时保留历史为 `HOLD`，确认后清空 episode | 未确认候选遇到 `+0.30°C/min` 回升可恢复；确认后需连续 5 个 `32~40°C` 样本且回到脱落前峰值 0.75°C 内，再进入新的 `CONTACT_SETTLING` |
| `STALE` | 序号长间隔，或约 3 秒没有新序号 | 清空派生时间线；读值为哨兵/NaN | 新样本到达后重新进入 `CONTACT_SETTLING` |

无效样本会清空历史；不会用最后一个值填补缺口。快速下降候选期间冻结 Core 模型，不把候选样本写入模型；确认脱离后清空 Core 历史和皮温字段。Core 模型和滤波历史在 `STALE` 后也必须重新初始化。头文件仍保留 `WARMING`/`STABLE` 兼容宏，分别映射到 `CONTACT_SETTLING`/`SKIN_TRUSTED`，新代码和新日志不得继续用旧名称表达 Core 是否准备完成。

板载诊断 LED 将两个状态机共同映射为可观察反馈：LED2 绿色只有在 `SKIN_TRUSTED + Core READY + FRESH + status=OK` 且实验 Core 正在导出时常亮；`CONTACT_SETTLING` 或 Core 五分钟预热时慢闪；无设备时快闪。LED3 蓝色继续提示 CRC、范围和未佩戴/脱离异常。LED 状态只用于调试，不改变 BLE 门控。

### 5.4 Core 独立状态机

| 状态 | 含义 | 对外行为 |
|---|---|---|
| `EMPTY` | 尚无可信皮温 episode | 无 Core |
| `WARMUP` | 已有可信皮温，但基线或完整 5 分钟历史尚未满足 | 自定义 CORE 继续发送 Skin，Core=`0x7FFF`；HTS/广播无 Core |
| `READY` | 基线、5 分钟历史、质量和数值门均通过 | `EXPERIMENTAL` 发布 Core V1；`STRICT` 还要求标定验证通过 |
| `HOLD` | 正在评估快速下降脱落候选 | Skin/Core 当前均无效，模型状态短时保留但不更新 |
| `INVALID` | 传输/佩戴 episode 无效，或模型目标越过 `35~42°C` 异常门 | 不发布 Core；越界值不会被钳制成 35 或 42°C |

### 5.5 质量、置信度和有效性

- `CONTACT_SETTLING`：质量 `POOR`，Contact 仅在内部可观察，Skin/Core 均不可发布。
- `SKIN_TRUSTED + 斜率未超限`：质量 `GOOD`，可信 Skin 可发布；Core 仍须等待 5 分钟历史，准备后无心率/有心率的实验置信度分别为 70/75。
- `SKIN_TRUSTED + 斜率超限`：质量 `FAIR`；普通短时变化仍可在 `EXPERIMENTAL` 中记录候选，准备后的无心率/有心率实验置信度分别为 60/65；进入脱离候选后输入立即冻结。
- 传输无效、未佩戴、陈旧：质量 `N/A`，置信度 0。
- 核心候选有效条件：`EXPERIMENTAL` 为存在模型参数、可信 Skin、佩戴基线、完整 5 分钟历史且质量至少 `FAIR`；`STRICT` 还要求质量至少 `GOOD`、置信度达到 `70`。
- 核心“已验证”条件：核心候选有效且标定文件明确写入 `RIDER_CORE_TEMP_CALIBRATION_VALID=1`。

## 6. Core V1 实验模型

### 6.1 模型形式

模型版本固定为 `RIDER_CORE_TEMP_MODEL_VERSION=1`，只表达胸带固定佩戴位置、骑行场景和个体化实验估算。设当前可信皮温为 `Ts`，本次佩戴最初 30 个可信皮温样本均值为 `Ts_baseline`，一分钟和五分钟前的可信皮温分别为 `Ts_1m`、`Ts_5m`，新鲜外部心率为 `HR`：

```text
target = base_core
       + skin_gain       * (Ts - 35.00°C)
       + baseline_gain   * (Ts - Ts_baseline)
       + trend_1m_gain   * (Ts - Ts_1m)
       + trend_5m_gain   * (Ts - Ts_5m)
       + [HR_gain        * (HR - 80 BPM)
          + HR_trend_gain * (HR - HR_1m)]   // 仅新鲜 HR 存在时

core_q8[n] = core_q8[n-1] + (target * 256 - core_q8[n-1]) * lag_alpha_q8 / 256
core[n] = round(core_q8[n] / 256)
```

当前无标定 header 时，`EXPERIMENTAL` 使用以下透明先验；这些值只为了稳定生成可导出的实验曲线，不是论文系数或已验证准确度：

| 参数 | 固件值 | 实际系数 |
|---|---:|---:|
| `base_core_centi` | `3680` | `36.80°C` |
| `skin_gain_q8` | `21` | `21/256 = 0.08203125` |
| `skin_delta_gain_q8` | `64` | `0.25` |
| `trend_1m_gain_q8` | `16` | `0.0625` |
| `trend_5m_gain_q8` | `32` | `0.125` |
| `heart_rate_gain_q8` | `256` | 每高于参考值 1 BPM，目标增加 `0.01°C` |
| `heart_rate_trend_gain_q8` | `32` | 每分钟心率差 1 BPM，目标增加 `0.00125°C` |
| `lag_alpha_q8` | `8` | `0.03125` |

历史每 5 秒保存一个点，61 个槽覆盖五分钟的两个端点；模型仍在每个约 1 Hz 的新样本上重新计算。因此“1 分钟/5 分钟”指特征回看窗口，不是 BLE 一分钟才更新一次。完整五分钟历史满足前，Skin 已可导出但 Core 必须保持无效。

实现还执行：

```text
target/core 必须位于 35.00°C~42.00°C，否则本次 Core 无效
|core[n] - core[n-1]| <= 0.25°C per second
```

首个 `READY` 目标直接初始化滞后状态；后续样本使用一阶滞后和速率限制。滞后状态保留 Q8 小数，皮温上升和下降使用对称定点路径。`35~42°C` 是异常检测门，不是人体正常范围，也不做边界钳制；将异常值钳成 35 或 42°C 会制造看似合理的假样本并污染码表导出。快速下降候选期间保留上一模型 Q8 状态，但 Skin/Core 都暂时无效；只有未确认候选被回升趋势取消后才恢复更新。`STRICT` 的全部系数必须由离线数据生成，且生成 header 的模型版本必须与固件 V1 一致。

### 6.2 心率输入边界

CORE Control Point `0x13` 接受外部心率并在约 15 秒没有刷新后失效。Core V1 的模式按每个候选动态选择：

- 有新鲜心率时为 `SKIN_AND_HR`，使用当前 HR 和一分钟 HR 变化；
- 没有或超时后为 `SKIN_ONLY`，两个 HR 项完全不参与，不把缺失值解释为 0 BPM；
- BLE Quality & State 仍按正式协议表示“支持但未收到”或“正在接收”，诊断字段 `heart_rate_used` 单独说明本次计算是否采用；
- 当前固件没有采集踏频、骑行功率、速度或环境温度，这些值也没有进入 Core V1；
- 当前不输出 HSI，也不输出医疗告警。

### 6.3 六圆柱 ScTM 的位置

经典六圆柱体温调节模型（ScTM）对骑行热负荷研究有参考价值，用户提供的资料摘要称其在最高约 1300 W 的骑行条件下得到验证，平均 RMSD 约 `0.2°C`。这个结果可作为后续实验设计和物理模型上限的参考，但不能直接移植为当前固件精度：ScTM 需要身体分段/组织热容、代谢热、机械功、环境温度、气流、服装和个体参数等边界条件，而当前设备只有一个固定胸部皮温点和可选心率。

因此当前实现不是 ScTM，而是可在 AC632N 上运行、可标定、可按源码逐项复现的 Core V1 经验动态模型。未来码表若能稳定提供功率、踏频、速度和环境温度，可在离线端把 ScTM 或简化热平衡模型作为独立对照；在找到并核对上述 RMSD 的原始论文、完整实验条件和受试者范围前，不把 `0.2°C` 写成当前产品指标。

## 7. BLE 编码与码表平均值

### 7.1 自定义 CORE 帧

CORE 温度帧为变长帧，字段按 Flags 顺序排列：

| 字段 | 当前策略 |
|---|---|
| Core | 始终存在；按当前发布模式可用时为核心候选，否则 `0x7FFF` |
| Skin | 只有 `SKIN_TRUSTED` 时附带固定胸带位置的可信皮温 |
| Quality & State | 始终带；低 4 位使用信号质量，高半字节按 CORE V2.2 表示外部心率接收状态 |
| Heart Rate | 只有 Control Point `0x13` 收到有效值时带出 |
| HSI | 暂不输出 |

当前 `EXPERIMENTAL` 在约 30 秒后进入 `SKIN_TRUSTED` 并约 1 Hz 发送可信 Skin；Core V1 `WARMUP` 阶段 Core 保持 `0x7FFF`，完整五分钟历史后进入 `READY` 并在同一帧带实验 Core。没有完成可信皮温门控、脱落候选或数据陈旧时不发送有效温度 Notification。`SHADOW` 可发送可信 Skin，但不发布 Core。

### 7.2 标准 Health Thermometer

`0x1809/0x2A1C` 只承担核心语义：

- 核心有效时使用 IEEE-11073 FLOAT，分辨率 `10^-2°C`；
- 核心不可用时使用 NaN mantissa `0x007FFFFF`，指数为 0；
- 影子模式不会把接触温度映射成标准核心温度；
- `0x2A1D` 独立返回 Temperature Type；
- 通知节拍约 10 秒，读取路径仍可返回当前哨兵值。

### 7.3 广播与平均值

- Manufacturer Specific Data 只在核心发布资格成立时带出温度；无效时省略温度字段。
- 断报和 `23°C` 不生成低温样本。
- 码表应对断报暂停平均统计或保持上一有效值，不能把缺失窗口按 0°C 或低温样本参与平均。
- 固件不维护平均温度、不发送平均字段，避免与码表的历史统计口径冲突。

## 8. 离线标定、验证与报告

### 8.1 输入数据

标定工具：`tools/rider_core_temp_calibrate.py`。

```text
timestamp,trusted_skin_centi,reference_core_centi,skin_state,heart_rate,heart_rate_valid,reference_skin_centi,session_id
```

支持：

- `trusted_skin_centi` / `reference_core_centi` 等百分之一摄氏度整数列；兼容旧的 `skin_centi`、`contact_centi` 和 `core_centi` 别名；
- `trusted_skin_c` / `reference_core_c` 等摄氏度列；
- `m601_raw`，按 `raw / 256 + 40` 转换；
- 可选参考皮温；
- 可选 `heart_rate` 和 `heart_rate_valid`；缺失或无效心率保留为“无特征”，不填 0；
- `skin_state=skin_trusted/core_ready/trusted` 才参与拟合，同时兼容旧的 `stable`、`3`、`ok`、`valid` 标签。

建议每条记录同时保存：原始 scratchpad、CRC 结果、固件序号、时间戳、佩戴状态、胸带位置/压力、参考核心温度来源、参考皮温位置、心率来源和环境条件。

### 8.2 拟合流程

1. 按 Session 和时间排序，去掉非可信皮温和缺少参考核心温度的行。
2. 每个 Session 用最初 30 个可信 Skin 建立佩戴基线，等待完整 5 分钟历史后生成模型就绪行。
3. 生成 `Ts-35°C`、`Ts-Ts_baseline`、1/5 分钟 Skin 变化，以及可选 `HR-80` 和一分钟 HR 变化七个仿射特征（含截距）。
4. 对一阶滞后 `lag_alpha_q8=1..255` 做网格搜索，并对每个候选拟合全部 V1 系数。
5. 将截距量化为百分之一摄氏度整数，其他增益量化为有符号 Q8。
6. 用与固件相同的 Q8 乘法、C99 有符号除法、滞后、每秒 `0.25°C` 限速、舍入和 `35~42°C` 无效门重新预测；越界计入无效预测，不做钳制。
7. 输出训练集与留出集的 RMSE、MAE、SEE、bias、95% 一致性界限（LoA）、`±0.3/±0.5°C` 覆盖率、无效预测数、浮点/定点差异和可选参考皮温摘要。

工具的最小命令：

```sh
python3 tools/rider_core_temp_calibrate.py samples.csv --output calibration.json --header apps/rider_core_temp/include/rider_core_temp_calibration.h
```

当前 CLI 对单一连续序列默认以前 80% 拟合、后 20% 连续留出。多时段实验应使用完整 Session 留出，命令示例为：

```sh
python3 tools/rider_core_temp_calibrate.py samples.csv \
  --holdout-session exercise \
  --output calibration.json \
  --header apps/rider_core_temp/include/rider_core_temp_calibration.h
```

`--holdout-session` 要求 CSV 提供 `session_id`（也接受 `session`）列，并会把整个时段从拟合集合移除；模型在该时段起点重新初始化。每个有效 Session 必须覆盖五分钟预热后仍有足够参考样本。不能把同一骑行时段拆到训练集和测试集两边，也不能随机打散时间点。生成 header 会写入 `RIDER_CORE_TEMP_CAL_MODEL_VERSION=1`；旧模型 header 与固件版本不匹配时编译直接失败，防止静默加载错误参数。

### 8.3 发布门槛

量化后的留出数据必须同时满足：

```text
RMSE <= 0.50°C
SEE  <= 0.50°C
|bias| <= 0.50°C
invalid_predictions == 0
```

且不能有明显的温度区间系统性偏差、运动/恢复阶段单独失效或重新佩戴后错误恢复。只有通过门槛并完成人工审查，生成 header 才可把 `RIDER_CORE_TEMP_CALIBRATION_VALID` 置为 `1`；随后还必须显式配置：

```c
#define RIDER_CORE_TEMP_PUBLISH_MODE RIDER_CORE_TEMP_PUBLISH_STRICT
```

门槛失败、数据不足、参考核心温度不可靠或跨时段偏差明显时，量产继续保持 `SHADOW`；板级 `EXPERIMENTAL` 只能继续用于明确标注的验证数据采集，不能据此宣称精度。

## 9. 验证矩阵

| 场景 | 期望状态/编码 | 通过标准 |
|---|---|---|
| 传感器未连接 | `NO_DEVICE`，核心 `0x7FFF`，HTS NaN | 不发有效温度，不进平均值 |
| CRC 错误 | 无效快照，清空历史 | 下一次有效样本重新预热 |
| 读数 `23°C` | `NOT_WORN` | 不通知、不广播、不进平均值 |
| 单点尖峰 | 中值/EWMA 抑制 | 不产生同幅核心跳变 |
| 序号重复/间隔过长 | `STALE` | 不桥接缺失，恢复后重新预热 |
| 连续约 3 秒无新序号 | `STALE` | 上一稳定值不再可发布 |
| 快速下降且 5 秒无回升 | `DETACH_SUSPECTED` | 下降累计至少 `0.50°C` 后确认；冻结核心模型并使 Skin/Core 无效 |
| 脱离后重新贴肤 | 连续 5 个 `32~40°C` 样本且回到脱落前峰值 0.75°C 内，再进入 `CONTACT_SETTLING` | 清空旧历史，重新完成 30 秒可信皮温和 5 分钟 Core 预热 |
| 五个典型皮肤样本 | 中值窗口填满，仍为 `CONTACT_SETTLING` | 不得提前发布 Skin 或更新 Core |
| 连续 30 个有效接触样本 | 第 30 个样本进入 `SKIN_TRUSTED` | 自定义 CORE 开始约 1 Hz 带可信 Skin；Core 仍为 `0x7FFF` |
| Core 五分钟预热 | `SKIN_TRUSTED + WARMUP` | Skin 持续导出；HTS/广播仍无 Core |
| Core 历史达到约 300 秒 | `READY` | 当前 `EXPERIMENTAL` 同帧发送 Skin/Core；约 1 Hz 更新 Core，HTS 约 10 秒 |
| 核心候选未验证（`SHADOW`） | CORE 核心 `0x7FFF`，HTS NaN | 绝不进入码表核心平均值 |
| `SKIN_TRUSTED + Core READY + EXPERIMENTAL` | CORE 同时带 Skin 和算法 Core 候选；HTS/广播带 Core 候选 | 码表可记录两路数据；Core 仍必须标记为实验值 |
| 严格模式且验证通过 | CORE/HTS/广播可带核心候选 | 参数、版本和报告可追溯 |
| Core 目标越过 `35~42°C` | `INVALID`，Core=`0x7FFF` | 不输出 35/42°C 边界假值，不污染导出 |
| `0x13` 外部心率 | `SKIN_AND_HR`；约 15 秒未刷新后回退 `SKIN_ONLY` | 未收到时不虚构心率；两条路径都连续更新而不重置 Skin 历史 |

cmake --build cmake-build-clion-ac632n-index --target ac632n_rider_core_temp_indexing -j2

## 10. 已知限制和风险

1. 本地 GT-M601 模块手册同时描述了模块 UART `115200 8N1` 的 ASCII 主动上报格式 `A+XX.XB` 加回车换行；当前 AC632N 固件走的是 PB7 直连传感器 1-Wire 路径，必须确认量产硬件没有把模块 MCU UART 输出误当作 PB7 传感器总线。
2. 正式 M601 芯片手册、CRC 多项式、寄存器定义和完整时序尚未进入本仓库；当前 CRC 和 `raw/256+40` 是基于随项目示例的集成假设。
3. `-40~125°C` 是当前固件保护窗，不是对芯片手册 `-70~150°C` 工作范围的替代声明。
4. 单人或小样本的核心估算只能作为固定位置、个体化运动趋势模型，不能跨人泛化，也不能用于医疗诊断或热应激告警。
5. 当前 Core 链路只采集 M601 温度和可选 Control Point 外部心率；没有采集踏频、功率、速度、环境温度、第二温度点、热流或湿度，不应期待 Core V1 具备多参数论文或 ScTM 的精度。
6. 真实测量要覆盖静息预热、持续运动、停止恢复、脱落/重新佩戴、不同环境和不同绑带压力；仅用平稳室温数据不能证明模型有效。

## 11. 后续迭代路线

### 阶段 A：当前实验采集基线

- 当前 AC632N 使用 `EXPERIMENTAL`：约 30 秒后先上报 Trusted Skin，Core V1 约 5 分钟后进入 `READY` 并同时上报；候选仍未通过验证，不得标记为已验证核心体温。
- 收集 Sensor/Trusted Skin/Experimental Core 三路温度、各自来源序号、皮温/Core 状态、质量、置信度、模型版本/模式、基线、1/5 分钟特征和新鲜度。
- 记录参考核心温度、参考皮温、心率、环境和运动阶段，但不把缺失特征填成 0。

### 阶段 B：个体化标定

- 固定胸骨位置、隔热结构和绑带压力。
- 按完整 Session 留出，分别检查静息、升温、运动、恢复和脱落段。
- 比较 Core V1 Skin-only、Skin+HR、简化热平衡和 ScTM 对照；任何新增模型都按完整骑行 Session 独立留出。
- 只有定点量化后仍通过门槛，才生成候选 header。

### 阶段 C：实板和码表验证

- 抓取码表是否真实写入 Control Point `0x13`。
- 检查 CORE Flags、皮肤字段、`0x7FFF`、HTS NaN 和广播省略行为。
- 检查断报时码表是否暂停平均统计，而不是把缺失转换成低温。
- 检查 PB7 的上拉、线长、噪声、供电和重启后的状态清空。

### 阶段 D：扩展模型（必须重新验证）

- 若码表链路能稳定提供踏频、功率、速度和环境温度，或硬件增加第二温度点、热流、环境湿度，再评估多参数模型；缺失特征不得填 0。
- 若要输出热应激等级，必须单独定义临床/运动生理风险边界和误报/漏报验收，不能从核心估算门槛直接推导。
- 若需要跨人泛化，必须扩大受试者、体型、性别、年龄、环境和运动强度范围，并做按人留出验证。

### 12.3 来源核验记录

- PMC 论文页面已核对题名、摘要、作者入口和 DOI；其中 Eggenberger 论文明确报告最小输入模型使用心率和绝缘皮温，SEE 约 `0.29°C`。
- Taylor、Gunga 和 Teunissen 条目的 DOI、题名和期刊元数据已通过 Crossref 公开记录核对；出版社页面可能存在反爬或付费限制，不能把未读取的全文细节写成已验证结论。
- 本地 M601 手册和仓库 `temp_sample` 是实现依据；手册未提供的 CRC 多项式和完整寄存器时序继续标为集成假设。
- 用户提供的六圆柱 ScTM 摘要（最高约 1300 W 骑行、平均 RMSD 约 `0.2°C`）目前尚未定位并核对原始论文、受试者和边界条件，因此只作为后续对照模型线索，不作为当前 Core V1 参数或性能证据。

### 12.4 研究证据等级

- `A`：论文正文/摘要或本地正式手册明确支持；可用于设计约束。
- `B`：公开协议或仓库示例支持；可用于接口和兼容实现，但仍需硬件确认。
- `C`：工程假设或产品初始窗口；只能作为可调参数，不能写成传感器事实。

当前记录：M601 换算和 CRC 假设为 `B/C`；`30~45°C` 佩戴窗、`32~40°C` 典型证据窗、30 秒可信皮温、5 分钟 Core 预热、3 秒 stale 和 Core V1 默认系数为 `C`；论文关于单点皮温边界和多参数必要性的结论为 `A`；尚未核对原文的 ScTM 数值为 `C`。
